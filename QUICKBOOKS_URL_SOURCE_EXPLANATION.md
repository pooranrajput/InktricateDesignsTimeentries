# QuickBooks Authorization URL - Complete Source Explanation

## Where That URL Comes From

The authorization URL you're asking about is generated by our system when you request it. Here's the exact source:

### Code Location: `server/quickbooks.ts` (lines 44-66)

```javascript
getAuthorizationUrl(state?: string) {
  const clientId = process.env.QUICKBOOKS_CLIENT_ID;
  const redirectUri = 'https://inkticate-time-tracker-pooranrajput.replit.app/api/quickbooks/callback';
  
  // Manual URL construction
  const baseUrl = 'https://appcenter.intuit.com/connect/oauth2';
  const params = new URLSearchParams({
    client_id: clientId || '',                           // AB6HieH2iCWWSQ8jneSClcttlAKuPHIcujzio09raTAQV5EUtA
    scope: 'com.intuit.quickbooks.accounting',          // Fixed scope
    redirect_uri: redirectUri || '',                     // Production callback URL
    response_type: 'code',                              // OAuth standard
    state: state || 'production-auth'                   // State parameter
  });
  
  return `${baseUrl}?${params.toString()}`;
}
```

1. **Base URL:** `https://appcenter.intuit.com/connect/oauth2` (QuickBooks OAuth endpoint)
2. **Client ID:** `AB6HieH2iCWWSQ8jneSClcttlAKuPHIcujzio09raTAQV5EUtA` (Your production app credentials)
3. **Scope:** `com.intuit.quickbooks.accounting` (Required for accounting data access)
4. **Redirect URI:** `https://inkticate-time-tracker-pooranrajput.replit.app/api/quickbooks/callback` (Where QB sends user back)
5. **Response Type:** `code` (OAuth authorization code flow)
6. **State:** `timetracking-reauth` (Anti-CSRF token)
